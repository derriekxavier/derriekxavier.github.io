The operational problem

Lenador runs a token-based access system tied to a catalogue of cultural and educational programs. Before this report, checking whether a user had an active token, or which programs had been recommended to them, meant querying the tables directly. This tool puts both views in front of a non-technical operator, searchable by name.

User Overview

A per-user token status table, paired with a searchable name filter and a list of programs recommended to each user, so an operator can look someone up and see their access status and recommendations at the same time.

The token status table and search filter sit next to each other so an operator searching for a name sees the result update right there, instead of jumping between pages.

Program Overview

The catalogue side: what programs exist, which category, and how they're scheduled, reported in Arabic and English side by side since the catalogue itself is bilingual.

Philosophy and Psychology, Literature, and Arts and Sports are the biggest categories. Of 99 total programs, 98 are active and 1 cancelled, a small number, but the kind of check that catches a data issue before it reaches an end user.

Why bilingual categories mattered

Showing Arabic and English category names as two parallel charts, instead of picking one, matches how the catalogue is actually maintained. Building the report around the data's real structure instead of simplifying it down to one language kept the tool usable for the whole team.

What I'd extend next

  • Add a date-range filter to the Program Overview page, beyond the current single-month view
  • Link token status directly to specific program recommendations, instead of listing them side by side
  • Add a simple export or print view for operators who need an offline token-status snapshot
