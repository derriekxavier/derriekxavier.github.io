Tokens & Programs Assignment

An internal Lenador tool built to answer two operational questions at once: which users currently hold an active token, and which cultural/educational programs are running and when — with the two views searchable and cross-referenced.

The operational problem

Lenador runs a token-based access system tied to a catalogue of cultural and educational programs. Before this report, checking whether a specific user had an active token — or which programs had been recommended to them — meant querying the underlying tables directly. This tool puts both views in front of a non-technical operator, searchable by name.

User Overview

A per-user token status table, paired with a searchable name filter and a list of programs recommended to each user — so a support operator can look up one person and immediately see both their access status and what's been recommended to them.

The design choice here was to keep the token-status table and the search filter visually adjacent, so an operator searching for a name sees the result and the underlying status table update together rather than needing to cross-reference a second page.

Program Overview

The catalogue side: what programs exist, in which category, and how they're scheduled — reported in both Arabic and English category names side by side, since the underlying program catalogue itself is bilingual.

Philosophy and Psychology, Literature, and Arts and Sports are the largest categories by program count. Of 99 total programs, 98 are active and 1 cancelled — a small enough number that the status split is more a sanity check than an analytical finding, but it's the kind of check that catches a data issue before it reaches an end user.

Why bilingual categories mattered

Reporting Arabic and English category names as two parallel charts, rather than picking one, was a direct response to how the catalogue itself is maintained — bilingually, for a bilingual audience. Building the report around the data's actual structure rather than simplifying it down to one language kept the tool usable for the whole team.

What I'd extend next

  • Add a date-range filter on the Program Overview page, beyond the current single-month view
  • Link token status directly to specific program recommendations, rather than listing them adjacently
  • Add a simple export/print view for operators who need an offline token-status snapshot
